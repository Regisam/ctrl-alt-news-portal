## Description

Implement comment threading with reply-to-reply support up to 3 nesting levels. Add parent_id foreign key to Comment schema, create reply endpoint, and implement hierarchical response structure. Support thread collapse/expand on frontend.

## Dev Agent Record (Dex) - Completed

### Implementation Summary

Successfully implemented complete comment threading system with 3-level nesting, depth validation, and hierarchical UI components.

**Backend:**
- Created `validateDepth()` utility (server/src/utils/validateDepth.ts) with recursive depth traversal
- Implemented `POST /api/comments/:id/reply` endpoint with:
  - Depth validation (max 3 levels, returns 400 on violation)
  - Parent comment validation (404 if not found)
  - Article consistency check
  - Winston logging for each reply creation
  - Parent context in response (id, content, author info)
- Implemented `DELETE /api/comments/:id` endpoint with:
  - Soft-delete of comment and recursive children
  - Preservation of thread structure (deletedAt timestamps)
  - Winston logging for deletions
- Updated Prisma schema: changed Comment.parent onDelete from Cascade to SetNull (enables soft-delete)
- Applied database migration: `prisma db push --force-reset` (dev environment)

**Frontend:**
- Created `client/src/components/Comment.tsx` - Recursive React component with:
  - Hierarchical rendering (comments → replies → nested replies)
  - Collapse/expand toggle for threads with replies
  - Reply count badge on collapse control
  - Parent context display (box showing parent author + excerpt)
  - Depth level indicator (Level 1, 2, 3)
  - Reply button (disabled at max depth)
  - Delete button (visible only for comment author)
  - Time formatting (now, Xm ago, Xh ago, Xd ago, date)
  - Author avatar, name, timestamp
  - Inline reply form placeholder (full form in Story 4.5)
  - Full accessibility (aria-labels, roles, semantic HTML)
  - Light/dark mode support (Tailwind classes)
