As a **recommendation system**, I want to **compute user-user similarities** from engagement patterns so that **I can identify users with similar interests and power collaborative filtering recommendations**.

## IN Scope

- **Similarity Computation**:
  - Pearson correlation on user engagement vectors
  - Cosine similarity as alternative metric
  - Similarity matrix as (user × user) sparse matrix
  - Handling tied scores and edge cases

- **User Engagement Vectors**:
  - Per-topic engagement (sum of normalized reads + bookmarks + reactions per topic)
  - Per-author engagement (normalized reads + bookmarks from each author)
  - Per-sentiment engagement (infer from article metadata, e.g., breaking news, analysis)
  - Temporal weighting (recent engagement counts more)

- **Embeddings & Caching**:
  - Dimensionality reduction (SVD or PCA to ~50D)
  - User embeddings cached for efficient similarity lookup
  - Embedding versioning (track when recomputed)

- **Batch Processing**:
  - Weekly batch job to compute full similarity matrix
  - Job can run offline (nightly, off-peak)
  - Incremental updates on new engagements

- **Monitoring & Dashboard**:
  - Coverage: % of users with ≥5 similar neighbors
  - Sparsity: density of similarity matrix
  - Similarity distribution: histogram of correlation scores
  - Computation time tracking

- **Tests**:
  - Unit: Pearson correlation accuracy, edge cases (all same value, negative correlation)
  - Integration: batch job runs without errors, matrix structure correct
  - Edge cases: new user (empty vector), inactive user, single-interest user

### Edge Case Handling

| Case | Handling |
|------|----------|
| **New user** | Empty engagement vector → 0 similarity to all users → flag for cold-start strategy |
| **Inactive user** | No recent engagement → low/zero vector → isolated in matrix |
| **Single-interest user** | All engagement in one topic → only similar to similar users → low coverage |
| **Identical users** | Perfect correlation (1.0) → rare, handled naturally |
| **Negative correlation** | Users with opposite interests → store as-is (useful information) |

## Risks & Mitigations

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| **Sparsity in matrix** (few neighbors) | Medium | Low | Use content-based fallback for cold-start users |
| **Correlation overfitting** (similar ≠ good taste) | Medium | Low | Validate with A/B test (Story 13.3) |

| **Embedding quality poor** | Low | Medium | Validate embeddings (t-SNE visualization) |
