## Technical Details

### Index Strategy

```sql
-- Indexes for foreign key relationships
CREATE INDEX idx_articles_category_id ON articles(category_id);
CREATE INDEX idx_articles_author_id ON articles(author_id);
CREATE INDEX idx_comments_article_id ON comments(article_id);
CREATE INDEX idx_comments_author_id ON comments(author_id);

-- Index for date-based filtering
CREATE INDEX idx_articles_published_at ON articles(published_at DESC);

-- Full-text search index
CREATE INDEX idx_articles_search ON articles USING GIN(search_tsvector);
```

### N+1 Query Pattern Fix

**Before (N+1)**:
```typescript
const articles = await prisma.article.findMany();
for (const article of articles) {
  article.author = await prisma.user.findUnique({ where: { id: article.authorId } });
  // Results in N+1 queries: 1 for articles + N for each author
}
```

**After (Eager Loading)**:
```typescript
const articles = await prisma.article.findMany({
  include: { author: true }  // Single query with JOIN
});
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Migration locks during index creation | Brief downtime | Create indexes CONCURRENTLY, test in staging first |
| Slow index creation on large tables | Production impact | Create indexes with CONCURRENTLY flag, schedule off-peak |
| Indexes degrade write performance | Slower inserts/updates | Monitor write performance, acceptable trade-off for read performance |
| Slow query logging overhead | Performance impact | Log only queries > 100ms, review periodically |
| Connection pool exhaustion | Connection timeouts | Configure appropriate pool size, monitor usage |
