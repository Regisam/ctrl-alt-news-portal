### Runbook Example: High Error Rate Troubleshooting

```markdown
## Troubleshooting: High Error Rate (5xx Errors)

**Symptom:** Alert "HttpErrorRateHigh" fired (error rate > 5%)

### Step 1: Verify Alert
- Go to Grafana dashboard "Ctrl Alt News - Application Metrics"
- Check "Error Rate (err/sec)" panel
- Confirm error rate > 5% and duration > 1 minute
- Note the time the error rate jumped

### Step 2: Check Logs
```bash
# SSH into server or use Loki dashboard
# Query for 5xx errors in past 30 minutes
{level="error"} | json | status_code >= 500

# Results show error distribution:
# - If 50% GET /api/articles → Database issue (Step 3a)
# - If 30% POST /api/comments → Service issue (Step 3b)
# - If spread across endpoints → Infrastructure issue (Step 3c)
```

### Step 3a: Database Issue
- Check PostgreSQL connection pool status
- Query PostgreSQL logs: high query latency, connection timeouts
- Look for long-running queries in pg_stat_statements
- If connections exhausted: restart database connection pool

### Step 3b: Service Issue
- Check service logs for exceptions (OutOfMemory, null pointer, etc.)
- Check system resources (CPU, memory) on service server
- If CPU high: check Grafana CPU panel, identify hot code path
- If memory high: check memory leak (see troubleshooting-memory-leak.md)

### Step 3c: Infrastructure Issue
- Check network connectivity between services
- Check firewall rules / security groups
- Check disk space on server (df -h)
- Verify downstream service health (dependency check)

### Step 4: Mitigate
- Temporary: Increase error threshold in AlertManager (reduce false alerts while investigating)
- Immediate: Scale up servers if under load
- Short-term: Apply fix to code and deploy new version
- Long-term: Add circuit breaker / retry logic to prevent cascading failures

### Step 5: Incident Documentation
- Log incident in status page / internal wiki
- Note root cause and resolution
- Schedule postmortem if critical (30+ min of >5% error rate)
```
