## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Denormalization accuracy | reply_count out of sync with actual replies | Increment/decrement on POST/DELETE reply, test accuracy with data audit query |
| Cache invalidation stale data | User sees old trending list | Invalidate cache on: new reply, delete reply, timestamp-based refresh at 5min |
| Depth calculation performance | Query timeout on large threads | Pre-calculate depth in reply creation (store depth field in Comment), use in trending response |
| Race condition on increment | reply_count increments missed | Use database transaction: `UPDATE ... SET reply_count = reply_count + 1` (atomic) |
| Trending window edge case | Comment created at 23:59, expires at 00:01 | Use precise timestamps, query: `createdAt >= NOW() - INTERVAL '24 hours'` |
