## Description

Optimize JavaScript bundle size and delivery through code splitting and asset optimization. Reduce Time to Interactive (TTI) and JavaScript parse/compile time by splitting the main bundle into smaller, route-based chunks that load on-demand. Target: reduce initial JS bundle from ~250KB to <150KB, improve Time to Interactive by 30-40%, maintain Lighthouse score ≥90.

**Business Impact:**
- Faster initial page load (fewer bytes to download)
- Reduced JavaScript processing time on slower devices
- Better performance on slow networks (3G/4G)
- Improved conversion rates from faster perceived load
- Supports EPIC-10 vision: organic traffic growth through performance

**Technical Context:**
- **Code Splitting**: Divide app into smaller chunks loaded on route change
- **Dynamic Imports**: Use ES modules to load features on-demand
- **Route-Based Splitting**: Each route component in own chunk
- **Vendor Splitting**: Separate third-party libraries from app code
- **Asset Compression**: Gzip/Brotli compression for all assets

## Acceptance Criteria

**Given** the app is built for production  
**When** bundle size is analyzed  
**Then** initial JS bundle <150KB (gzipped)

**Given** a user navigates to an article page  
**When** the route loads  
**Then** article-specific code loads on-demand (not in main bundle)

**Given** Lighthouse audit runs  
**When** performance metrics are calculated  
**Then** Time to Interactive <3 seconds (mobile), <2 seconds (desktop)

**Given** bundle analysis is run  
**When** vendor and app chunks are compared  
**Then** vendor libraries separated from app code (no duplication)

**Given** static assets are served  
**When** compression is applied  
**Then** all assets served with gzip or brotli (>80% reduction)

**Given** bundle size changes occur  
**When** performance regression tests run  
**Then** no bundle size increase >5% without approval

## Tasks

- [ ] Task 1: Measure & Baseline Bundle Size
  - Measure current main bundle size (gzipped & ungzipped)
  - Analyze bundle composition (vendor, app, unused code)
  - Identify heavy dependencies
  - Document baseline metrics

- [ ] Task 2: Implement Route-Based Code Splitting
  - Convert route components to lazy-loaded modules
  - Implement React.lazy() for each route
  - Add Suspense boundaries with loading states
  - Test bundle splitting results

- [ ] Task 3: Optimize Vendor Bundle
  - Separate vendor code from app code
  - Identify unused dependencies
  - Consider dependency alternatives
  - Verify chunk output in build

- [ ] Task 4: Asset Compression & Headers
  - Verify gzip compression on static assets
  - Consider brotli compression for modern browsers
  - Validate compression headers (content-encoding)
  - Test decompression in browsers

- [ ] Task 5: Measure & Validate Performance
  - Measure Time to Interactive (TTI) improvement
  - Run Lighthouse audit (target: ≥90 performance)
  - Compare before/after bundle metrics
  - Create performance regression tests
