## Technical Details

### Logging Stack Selection

**Option A: Winston (Recommended)**
- Mature, widely used, good performance
- Multiple transports (file, HTTP, custom)
- Built-in filtering & formatting

**Option B: Pino**
- Ultra-fast, low overhead
- Minimal dependencies
- Good for high-volume scenarios

**Decision**: Winston for flexibility, Pino as alternative if performance critical.

### Log Structure (JSON)

```json
{
  "timestamp": "2026-04-24T10:30:45.123Z",
  "level": "info",
  "service": "ctrl-alt-news-server",
  "request_id": "req-12345",
  "user_id": "user-999",
  "message": "Article retrieved successfully",
  "duration_ms": 42,
  "context": {
    "article_id": "art-5678",
    "endpoint": "/api/articles/:id"
  }
}
```

### Client Logging

```typescript
// client/src/lib/logger.ts
export function log(level, message, context?) {
  // Sanitize: remove passwords, tokens, PII
  const safe = sanitize(context);
  // Send to server or local storage
  fetch('/api/logs', { method: 'POST', body: JSON.stringify({level, message, safe}) })
}
```

### Client-Side API Schema

**POST /api/logs**

Request:
```json
{
  "level": "info|warn|error",
  "message": "User action description",
  "context": {
    "page": "/articles/search",
    "user_id": "user-123",
    "session_id": "sess-456",
    "custom_metric": "value"
  },
  "timestamp": "2026-04-24T10:30:45.123Z"
}
```

Response:
```json
{
  "status": "ok",
  "log_id": "log-789"
}
```

**Important:** Context is sanitized before sending — passwords, tokens, credit card data removed automatically.
