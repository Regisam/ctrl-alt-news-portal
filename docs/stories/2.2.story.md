## Story

**As a** site reader  
**I want** to post comments on articles and see them persisted  
**So that** I can engage with other readers and contribute to the discussion

---

## Description

The CommentsSection component (`client/src/pages/ArticleDetail.tsx` lines 437-443) currently uses mock comment data. This story implements real backend persistence by:

1. Creating GET/POST endpoints for comments (`/api/comments` and `/api/comments/:id`)
2. Implementing comment threading (replies to comments)
3. Validating comment content server-side
4. Storing comments in database using existing `Comment` Prisma model (Sprint 1)
5. Connecting frontend CommentsSection to real API instead of mock data
6. Adding pagination for large comment threads

---

## Acceptance Criteria

### AC1: List Comments Endpoint
**Given** a GET request to `/api/comments?articleId=<id>&page=1&limit=20`  
**When** article exists and has comments  
**Then** returns 200 + array of comments with: id, content, author, createdAt, parentCommentId (for threading)

### AC2: Create Comment Endpoint
**Given** POST to `/api/comments` with: `{ articleId, content, authorId, parentCommentId? }`  
**When** data is valid  
**Then** returns 201 + created comment object with id, createdAt, etc.

### AC3: Comment Validation
**Given** POST `/api/comments` with invalid/empty content  
**When** content is < 5 chars or > 5000 chars  
**Then** returns 400 + error: "Comment must be 5-5000 characters"

### AC4: Comment Threading
**Given** comment is reply to another comment (parentCommentId provided)  
**When** POST `/api/comments` succeeds  
**Then** comment stored with parentCommentId, frontend displays as nested reply

### AC5: Frontend Integration
**Given** user is viewing ArticleDetail page  
**When** page loads  
**Then** CommentsSection fetches comments from GET `/api/comments?articleId=X` (not mock)

### AC6: Add Comment Form
**Given** user fills comment form and clicks "Post Comment"  
**When** form is valid and POST succeeds  
**Then** new comment appears in thread immediately + form clears

### AC7: Error Handling
**Given** API request fails (500, network, timeout)  
**When** user submits comment or page loads  
**Then** error message displays: "Failed to load/post comments. Please try again."

## Dev Notes

### Data Model (Existing from Sprint 1)

```prisma
model Comment {
  id                String   @id @default(cuid())
  content           String   @db.Text
  articleId         String
  authorId          String
  parentCommentId   String?  // For threading (reply to another comment)
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
  deletedAt         DateTime? // Soft delete

  article           Article  @relation(fields: [articleId], references: [id], onDelete: Cascade)
  author            User     @relation(fields: [authorId], references: [id], onDelete: Cascade)
  parentComment     Comment? @relation("Replies", fields: [parentCommentId], references: [id], onDelete: Cascade)
  replies           Comment[] @relation("Replies")

  @@index([articleId])
  @@index([authorId])
  @@index([parentCommentId])
  @@index([createdAt])
}
```

### Endpoint: GET `/api/comments`

**Query Params:**
- `articleId` (required): UUID of article
- `page` (optional, default: 1): pagination page
- `limit` (optional, default: 20): comments per page
- `sort` (optional, default: "newest"): "newest" or "oldest"

**Response (200 OK):**
```json
{
  "success": true,
  "data": [
    {
      "id": "cly9x8zq20000qz8z9x9x9x9x",
      "content": "Great article! Totally agree with your take on AI ethics.",
      "author": {
        "id": "user-123",
        "name": "Jane Smith",
        "avatar": "initials or gravatar"
      },
      "createdAt": "2026-04-18T10:30:00Z",
      "parentCommentId": null,
      "replies": [
        {
          "id": "cly9x8zq20000qz8z9x9x9x9y",
          "content": "Thanks! I've been following this debate closely.",
          "author": { "id": "user-456", "name": "Marcus Chen" },
          "createdAt": "2026-04-18T11:15:00Z",
          "parentCommentId": "cly9x8zq20000qz8z9x9x9x9x"
        }
      ]
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 47,
    "totalPages": 3
  }
}
```

### Endpoint: POST `/api/comments`

**Request Body:**
```json
{
  "articleId": "article-123",
  "content": "Excellent piece. The section on neural networks was particularly insightful.",
  "authorId": "user-789",
  "parentCommentId": null
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "data": {
    "id": "cly9x8zq20000qz8z9x9x9xzz",
    "content": "Excellent piece...",
    "author": { "id": "user-789", "name": "Alice Johnson" },
    "createdAt": "2026-04-18T12:00:00Z",
    "parentCommentId": null
  }
}
```

### Threading Logic

**Example thread structure:**
```
Comment A (parentCommentId: null)
├── Reply A1 (parentCommentId: A)
└── Reply A2 (parentCommentId: A)

Comment B (parentCommentId: null)
└── Reply B1 (parentCommentId: B)
    └── Reply B1a (parentCommentId: B1) ← LIMIT TO 2 LEVELS MAX
```

**Frontend render:** Display top-level comments, with replies indented below.
