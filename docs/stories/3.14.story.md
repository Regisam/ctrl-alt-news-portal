## Description

Implement login history tracking and active session management. Users can view their login history (IP, device, timestamp, location), manage active sessions, and revoke specific sessions. Helps detect unauthorized access and provides security transparency.

**Reference**: PRD section 2.9 (Security & Privacy), GDPR data subject access rights

## Acceptance Criteria Details

### Data Structures

**LoginEvent**
```typescript
{
  sessionId: string;          // Unique session identifier
  timestamp: number;          // Unix timestamp of login
  ipAddress: string;          // Client IP address
  userAgent: string;          // Raw user agent string
  browser: string;            // Parsed: Chrome, Firefox, Safari, etc.
  os: string;                 // Parsed: Windows, macOS, iOS, Android
  deviceType: string;         // Parsed: desktop, mobile, tablet
  type: 'local' | 'oauth';    // Authentication method
  status: 'success' | 'failed'; // Login result (for Phase 2)
}
```

**Session (Active)**
```typescript
{
  sessionId: string;
  loginTime: number;
  lastActivity: number;
  ipAddress: string;
  browser: string;
  os: string;
  deviceType: string;
  isCurrent: boolean;
}
```

### API Endpoints

**GET /api/auth/sessions**
```
Headers: Authorization: Bearer {token}
Response (200): { success: true, sessions: Array<Session> }
Response (401): { success: false, error: "Unauthorized" }
```

**GET /api/auth/login-history**
```
Headers: Authorization: Bearer {token}
Query: ?days=30 (optional)
Response (200): { success: true, history: Array<LoginEvent>, total: number }
Response (401): { success: false, error: "Unauthorized" }
```

**DELETE /api/auth/sessions/:sessionId**
```
Headers: Authorization: Bearer {token}
Response (200): { success: true, message: "Session revoked" }
Response (400): { success: false, error: "Cannot revoke current session" }
Response (401): { success: false, error: "Unauthorized" }
Response (404): { success: false, error: "Session not found" }
```

**DELETE /api/auth/sessions/others**
```
Headers: Authorization: Bearer {token}
Response (200): { success: true, message: "All other sessions revoked", count: number }
Response (401): { success: false, error: "Unauthorized" }
```

### Security Considerations
- Session IDs are unique and random (use crypto.randomBytes)
- IP addresses not exposed in regular API responses (security)
- User agent parsing on backend (client can't spoof)
- Current session cannot be self-revoked (prevents lockout)
- Login history limited to user's own data (auth check)
- Expired sessions removed periodically

### Logging
- Login event (user, IP, device, timestamp)
- Session retrieval (debug)
- Session revocation (info, sessionId)
- Bulk revocation (info, count)
- History access (debug)
- Unauthorized attempts (warn)
