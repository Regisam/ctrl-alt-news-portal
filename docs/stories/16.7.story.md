## Story

As a **operations team**, I want to **monitor the health of external dependencies** so that **I can detect when critical services fail and respond before they impact users**.

**Context:**
- Story 16.1 monitors server health only
- No visibility into database, cache, external APIs
- Service degradation often caused by dependency issues
- Need: Comprehensive dependency health checks

## Dev Notes

### Blockers
None identified.

### Gotchas
- Timeout handling: don't block health endpoint
- Database connection exhaustion: use separate pool for checks
- Circuit breaker vs circuit open: when to disable service?
- Cascading failures: if DB down, cache also unavailable?
- False positives: brief glitches shouldn't trigger alerts
