## Story

As a **security team**, I want to **harden the application against common attacks** so that **users' data is protected and the service remains available**.

**Context:**
- Application currently lacks security headers
- No input validation/sanitization on most endpoints
- Missing HTTPS enforcement
- No CSRF protection
- Rate limiting exists (16.4) but not on auth endpoints
- Cookies may not be secure
- Error messages may leak sensitive info

## Dev Notes

### Blockers
None identified.

### Gotchas
- Security headers can break UI (CSP too strict)
- HTTPS enforcement breaks dev server (use --secure)
- Rate limiting can affect legitimate users
- Password complexity vs usability trade-off
- Error messages: helpful for dev, dangerous for prod
