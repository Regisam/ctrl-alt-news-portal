## Description

Optimize Core Web Vitals metrics (LCP, FID, CLS) which are critical Google ranking factors. These three metrics directly impact SEO visibility and user experience. Current baseline (from Story 10.7): LCP ~3.2s, FID ~50ms, CLS ~0.08. Target: achieve GREEN status on all three metrics to improve Lighthouse scores from 65→90+ and increase organic traffic by 15-20%.

**Business Impact:**
- Improves Google Search ranking (Core Web Vitals are ranking signals)
- Enhances user experience on mobile devices (key for conversion)
- Reduces bounce rate for users on slower connections
- Supports EPIC-10 vision: organic traffic growth through performance optimization

**Technical Context:**
- LCP (Largest Contentful Paint): Time when largest visual element loads (<2.5s target)
- FID (First Input Delay): Time from user interaction to browser response (<100ms target)
- CLS (Cumulative Layout Shift): Visual stability during page load (<0.1 target)

**Reference**: EPIC-10 (Growth & Discovery), Phase 3: Performance  
**Prerequisite**: Story 10.7 (Image Optimization) ✅

## Scope

**IN SCOPE:**
- LCP optimization: lazy loading, critical CSS, font preloading, image optimization
- FID optimization: code splitting, third-party script deferral, JavaScript execution
- CLS optimization: font-display settings, layout stability, reserved space for ads
- Lighthouse audit & scoring validation
- Core Web Vitals monitoring dashboard
- Performance regression tests

**OUT OF SCOPE:**
- Server-side rendering implementation (separate initiative)
- CDN configuration (infrastructure team)
- Third-party ad optimization (external vendors)
- Database query optimization (Story 10.9)

## Acceptance Criteria

**Given** a user visits the Ctrl Alt News portal on a mobile device  
**When** the page begins loading  
**Then** Largest Contentful Paint occurs within 2.5 seconds

**Given** a user clicks a button or link on the page  
**When** the browser registers the interaction  
**Then** the browser responds within 100 milliseconds (First Input Delay)

**Given** the page renders images, fonts, and layout elements  
**When** the page fully loads  
**Then** Cumulative Layout Shift remains below 0.1 (visual stability maintained)

**Given** Lighthouse audit runs on article page  
**When** performance scoring is calculated  
**Then** Mobile Lighthouse score ≥90 and Desktop ≥95

**Given** Core Web Vitals optimization is deployed  
**When** monitoring system collects metrics  
**Then** 90%+ of sessions achieve GREEN status for all three metrics

**Given** performance regression test suite runs  
**When** new code is deployed  
**Then** no performance regression detected (LCP, FID, CLS within ±10% baseline)

## Tasks

- [ ] Task 1: Measure & Baseline Web Vitals
  - Run Lighthouse audit on mobile & desktop
  - Collect Real User Monitoring (RUM) data
  - Identify current bottlenecks (LCP, FID, CLS)
  - Document baseline metrics in performance log

- [ ] Task 2: Optimize LCP (Largest Contentful Paint)
  - Identify largest visual element on critical pages
  - Implement image lazy loading (already done in 10.7)
  - Optimize font loading (font-display: swap)
  - Defer non-critical CSS/JS
  - Preload critical resources
  - Add Web Worker for heavy computation
  - Measure LCP improvement

- [ ] Task 3: Optimize FID (First Input Delay)
  - Analyze JavaScript execution time
  - Code-split large bundles
  - Defer non-critical JavaScript
  - Remove or defer third-party scripts
  - Profile interaction handlers
  - Measure FID improvement

- [ ] Task 4: Optimize CLS (Cumulative Layout Shift)
  - Audit layout shifts during page load
  - Set dimensions for images/ads (reserved space)
  - Fix font loading causing layout shift
  - Ensure animations don't cause shift
  - Validate spacing/padding consistency
  - Test with slow 3G connection
  - Measure CLS improvement

- [ ] Task 5: Validate & Monitor
  - Run Lighthouse audit (target: 90+ mobile, 95+ desktop)
  - Implement Core Web Vitals monitoring
  - Create performance dashboard
  - Set up performance regression tests
  - Document optimization techniques used
  - Add to CI/CD pipeline

## Testing Strategy

- **Unit Tests**: Performance utility functions (metric calculations, thresholds)
- **Integration Tests**: Performance metrics collection across page lifecycle
- **Lighthouse Audits**: Mobile & desktop performance scoring (90+/95+ targets)
- **Real User Monitoring**: Collect actual user metrics (RUM data)
- **Regression Testing**: Ensure no performance degradation in future updates
- **Browser Testing**: Performance validation in Chrome, Firefox, Safari, Edge
- **Network Throttling**: Test with simulated slow 3G, 4G connections
- **Device Testing**: Mobile (iPhone, Android) and desktop performance

---

## Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| Third-party scripts impact FID | Medium | High | Identify heavy scripts, defer or sandbox them |
| Font loading causes CLS | Medium | Medium | Use font-display: swap, set font dimensions |
| Lazy loading breaks critical content | Low | High | Lazy load only below-the-fold content |
| Performance degrades in slow networks | Low | Medium | Test with network throttling enabled |
| Regression after future updates | Medium | Medium | Add performance regression tests to CI/CD |
