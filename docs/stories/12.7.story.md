## Technical Details

### useSmartDigest Hook
```typescript
interface SmartDigestConfig {
  enabled: boolean;
  frequency: 'daily' | 'weekly';
  preferredTime: string; // '08:00' UTC
  topics: string[]; // user's topic preferences
  lastDigestSent?: Date;
}

interface DigestArticle {
  id: string;
  title: string;
  summary: string;
  link: string;
  category: string;
  relevanceScore: number;
  reason: string; // why recommended (topic match, trending, etc.)
}

interface SmartDigestPayload {
  userId: string;
  digestDate: Date;
  articles: DigestArticle[]; // top 3-5
  config: SmartDigestConfig;
  unsubscribeToken: string; // one-time use
  preferencesToken: string; // one-time use for settings
}

function useSmartDigest() {
  const config = getDigestConfig(); // from localStorage
  const userInterests = getTopicInterests(); // from EPIC-11 data
  
  // Fetch recommendations from EPIC-12 rules engine
  const candidates = getRuleBasedRecommendations(userInterests);
  
  // Score and rank
  const ranked = rankByRelevance(candidates, userInterests);
  const topArticles = ranked.slice(0, 5);
  
  // Generate payload with tokens
  const digest = {
    userId: getCurrentUser().id,
    digestDate: new Date(),
    articles: topArticles,
    config,
    unsubscribeToken: generateOneTimeToken('unsubscribe'),
    preferencesToken: generateOneTimeToken('preferences'),
  };
  
  return digest;
}
```

### Scheduling Logic
- **Batch job** runs every 4 hours to check if digest should be sent for any user
- **Per-user trigger**: `(lastDigestSent + frequency) <= now`
- **Time zone aware**: Convert UTC to user's preference (or default UTC)
- **Retry on failure**: 3 attempts with exponential backoff

### Analytics Integration
- **Open tracking**: Invisible pixel in email footer (1x1 px image)
- **Click tracking**: Proxy links through `/api/digest/click/:token/:articleId`
- **Unsubscribe**: Direct API call `/api/digest/unsubscribe/:token`
- **Storage**: localStorage JSON with metrics per digest sent

## Dev Notes

### Tech Stack Decisions
- **Email Service**: Use SendGrid (simpler) or AWS SES (cheaper at scale)
- **Scheduling**: Node.js `node-cron` or built-in interval timer (simple enough for MVP)
- **Storage**: localStorage for preferences (client-side) + email service logs (server)
- **Templates**: Use handlebars or simple template literals (keep it simple)

### Performance Targets
- Digest generation: <2s (includes API calls to recommendation engine)
- Email send: <1s per email
- Scheduling batch: run every 4h, process all users in <5min

### Security Considerations
- One-time tokens: 32-char random strings, expire after 24h or first use
- No user data in email links (only tokens)
- Validate token on unsubscribe/preference update
- Bounce handling: automatic removal from list

### Testing Strategy
- **Unit**: Digest ranking, scheduling logic, token generation
- **Integration**: Email template rendering, SendGrid API calls (mock)
- **E2E**: Preference update → digest sent → open/click tracked
- **Load**: Test with 100+ users getting digest same time (avoid thundering herd)
