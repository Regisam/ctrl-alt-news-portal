## Story

As a **engineering team**, I want to **aggregate and analyze error patterns in production** so that **we can identify root causes, fix systemic issues, and improve reliability**.

**Context:**
- Story 16.1 logs all errors to files + logger
- Currently: no way to see error patterns (what errors are common?)
- Need: Error grouping by type/message/stack trace
- Goal: Find which errors matter most + prevent regressions

## IN Scope

- Error grouping by fingerprint (type + normalized stack)
- Frequency tracking (count, first/last seen, timeline)
- Severity classification (based on error type/impact)
- User impact analysis (how many users affected)
- Error dashboard integration (add tab to Story 16.3 dashboard)
- Export functionality (CSV/JSON)
- Error spike detection (10x threshold)
- Request replay data (headers, body, user, timestamp)
- Pattern search (regex/substring)
- Historical data (30-day retention)

---

## OUT of Scope

- Machine learning-based anomaly detection
- Automatic error fix suggestions
- Integration with external error tracking (Sentry, Rollbar)
- Mobile app error tracking
- Client-side error aggregation (separate story)

## Dev Notes

### Blockers
None identified.

### Gotchas
- Error data can grow large (storage/memory) — implement cleanup
- Stack traces vary (line numbers change) — normalize before grouping
- User privacy: don't log sensitive data in errors
- Time zones: use UTC for storage, convert for display
- Error fingerprinting: hash algorithm must be stable
