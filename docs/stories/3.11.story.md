Implement secure password reset flow with email-based verification tokens. Users can request password reset via email, receive a unique token with 1-hour expiration, and set a new password via secure endpoint. Prevents token reuse and logs all reset attempts.

## Acceptance Criteria Details

### Security Requirements
- Reset tokens: 32-byte random (256 bits) via crypto.randomBytes()
- Expiration: 1 hour (3600000ms) - shorter window than email verification
- One-time use: Token deleted immediately after successful password change
- Rate limiting: Max 1 reset request per email every 5 minutes (prevent spam/brute force)
- Password validation: Minimum 8 characters (consistent with registration)
- Hashing: bcrypt with 10 salt rounds (same as registration)

### API Endpoints

**POST /api/auth/forgot-password**
```
Request: { email: string }
Response (200): { success: true, resetLink: string, message: string }
Response (400): { success: false, error: "Email is required" | "Too many requests, try again in X minutes" }
Response (404): { success: false, error: "User not found" }
```

**GET /api/auth/reset-password/:token**
```
Response (200): { success: true, valid: true, email: string }
Response (400): { success: false, error: "Reset token expired", valid: false }
Response (404): { success: false, error: "Reset token not found", valid: false }
```

**POST /api/auth/reset-password/:token**
```
Request: { password: string }
Response (200): { success: true, message: "Password reset successfully" }
Response (400): { success: false, error: "Password must be at least 8 characters" | "Reset token expired" }
Response (404): { success: false, error: "Reset token not found" | "User not found" }
```

### Error Handling
- Invalid email format: 400 (caught by frontend validation too)
- User not found: 404 (don't expose whether email exists)
- Too many requests: 400 with cooldown message
- Invalid/missing token: 404
- Expired token: 400 (token auto-deleted)
- Invalid password: 400

### Logging (Winston)
- Reset request received (email, timestamp)
- Rate limit check (allow/deny with remaining wait time)
- Token generation (token created with expiration)
- Token validation (valid/expired/missing)
- Password reset success (email, timestamp)
- All errors (with full context for debugging)
