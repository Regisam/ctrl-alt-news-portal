## 🚨 Monitoring & Alerting Rules

### Alert Thresholds

| Alert | Condition | Severity | Action |
|-------|-----------|----------|--------|
| **High Latency** | p99 > 150ms for 5 min | WARNING | Check ranking load, consider scaling |
| **CTR Regression** | Control CTR drops > 5% | CRITICAL | Investigate data pipeline, check for bugs |
| **Engagement Drop** | Treatment time-on-article < 80% of control | HIGH | Review serendipity weight, may need tuning |
| **Embedding Stale** | Last update > 8 days | MEDIUM | Trigger Story 13.4 update |
| **Cold-Start Fail** | New user discovery rate < 10% | HIGH | Debug cold-start logic |
| **Feature Flag Inconsistency** | User switch variants | CRITICAL | Investigate deterministic bucketing |
| **Test Failure** | Any critical test fails | CRITICAL | Block deployment, investigate |

### Alert Channels

- **CRITICAL**: PagerDuty + Slack #serendipity-alerts
- **HIGH**: Slack #serendipity-alerts + daily digest
- **MEDIUM**: Grafana dashboard + weekly review
- **INFO**: Dashboard only

## 🔄 Rollback Procedures

### Immediate Rollback (Catastrophic Issue)

```
If ANY of these occur:
  🛑 CTR drops > 10% (vs control baseline)
  🛑 Latency p99 > 200ms (system overload)
  🛑 Bucketing breaks (user switches between variants)
  🛑 Rankings not updating (stale recommendations)
  🛑 Database errors in recommendation pipeline

Actions:
  1. Declare incident in #serendipity-alerts
  2. Immediate: Set rollout_percentage = 0 (disable)
  3. Investigate: Check logs, error rates, query performance
  4. Communicate: Update status, give timeline
  5. Fix: Deploy fix or rollback code
  6. Verify: Run tests again before re-enabling
  7. Redeploy: Start from Canary (5%) again
```

### Graceful Rollback (Slow Degradation)

```
If metrics are trending negative but not catastrophic:
  ⚠️ CTR trending down 2-3% per day
  ⚠️ Engagement plateau (not improving after 3 days)
  ⚠️ User complaints about "too much randomness"

Actions:
  1. Hold rollout at current percentage
  2. Investigate: Review serendipity weight, diversity constraints
  3. Options:
     a) Reduce weight (0.15 → 0.10)
     b) Increase diversity (max 2 articles/topic → max 1)
     c) Investigate embedding staleness
  4. Deploy fix to canary first
  5. A/B test new configuration
  6. If improved: proceed with new config
  7. If not: full rollback
```
