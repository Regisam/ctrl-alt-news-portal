## Acceptance Criteria Details

### Deletion Process
1. Authenticate user with JWT token
2. Require password confirmation (prevents accidental deletion)
3. Verify password matches user's bcrypt hash
4. Delete user record from users Map
5. Delete all associated tokens (refresh, reset, verification)
6. Clear authentication cookie
7. Log deletion event
8. Return success

### API Endpoint

**DELETE /api/auth/account**
```
Headers: Authorization: Bearer {token}
Request: { password: string }
Response (200): { success: true, message: "Account deleted successfully" }
Response (400): { success: false, error: "Password is required" | "Incorrect password" }
Response (401): { success: false, error: "Unauthorized" }
Response (404): { success: false, error: "User not found" }
```

### Data Cleanup
- User record: deleted from users Map
- Refresh tokens: all deleted from refreshTokens Map
- Reset tokens: all deleted from resetPasswordTokens Map
- Verification tokens: all deleted from verificationTokens Map
- httpOnly cookie: cleared
- No residual data remains

### Security Requirements
- Password confirmation required (prevents accidents)
- Permanent deletion (no soft delete or recovery)
- JWT authentication required
- Proper HTTP status codes
- No sensitive data in responses

### Logging
- Deletion request (email, timestamp)
- Password verification (attempt)
- Token cleanup count
- Final deletion confirmation
