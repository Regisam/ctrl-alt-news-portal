## Dev Notes

### Context
- Dashboard location: `client/src/pages/TopicRecommendationsMonitoringPage.tsx`
- Analytics module: `client/src/lib/topicRecommendationsAnalytics.ts`
- Real data source: Supabase tables:
  - `user_recommendations` (variant assignments)
  - `user_topic_interactions` (engagement data)
  - `articles` (content)

### Key Queries to Implement
1. `getVariantAnalyticsFromSupabase()` — Main metrics aggregation
2. `getDailyMetricsByVariant()` — Trend data
3. `getMetricsByUserSegment()` — New vs returning analysis
4. `detectWinningVariant()` — Statistical significance testing

### Estimated Effort Breakdown
- Supabase query implementation: 2h
- Dashboard integration: 1.5h
- Statistical testing: 1h
- Alerting system: 0.5h
- Testing & validation: 1h

### Risks
- **Query Performance:** Supabase aggregation queries might exceed 2s timeout on large datasets
- **Data Consistency:** Real production data may not match AC4-5 targets (adoption ≥15%, lift ≥8%) — may require tuning
- **Variant Mapping:** A/B test variant IDs must correctly correlate with user_recommendations table schema
- **Alert False Positives:** Alert thresholds (<10% adoption) may trigger incorrectly on day 1 if data is incomplete
- **Dependency Timing:** Story 14.1 must be deployed to production BEFORE this story implementation starts
