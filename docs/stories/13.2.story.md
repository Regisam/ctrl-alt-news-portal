## Story

As a **recommendation system**, I want to **discover articles through item-item collaborative filtering** so that **I can recommend articles that similar users have engaged with, even if the current user hasn't read similar topics**.

**Context:**
- Story 13.1 (user similarity) is now complete — provides user vectors and embeddings
- EPIC-12 established rules engine and content similarity (Story 12.5)
- Item CF is complementary: content similarity finds articles about same topic; item CF finds articles similar users read
- Prerequisite for Story 13.3 (hybrid engine)

## IN Scope

- **Item Similarity**:
  - Jaccard similarity on user read sets (intersection/union of readers)
  - Cosine similarity on engagement vectors per item
  - Item-item similarity matrix (article × article)
  - Handling new articles (cold start)

- **Co-engagement Matrix**:
  - Articles read together by same users
  - Weight by engagement strength (scroll depth, bookmarks)
  - Temporal weighting (recent co-reads more important)

- **CF Recommendation Generation**:
  - For target user: find similar users (from Story 13.1)
  - Collect articles read by similar users (not read by target)
  - Score by item similarity × user similarity × article recency
  - Return top-K recommendations

- **Coverage & Fallbacks**:
  - For new articles: use content-based similarity (Story 12.5) as fallback
  - For sparse coverage: blend with rules engine (Story 12.1) scores
  - For niche articles: ensure diversity in results

- **Tests**:
  - Unit: Jaccard/cosine similarity, edge cases
  - Integration: CF recommendation generation end-to-end
  - Edge cases: new article, unpopular article, highly read article

### Co-Read Matrix Example

```
User A reads: [Article 1, Article 3]
User B reads: [Article 1, Article 2, Article 3]
User C reads: [Article 2, Article 4]

Co-read matrix:
Article 1 <-> Article 3 (both read by A, B)
Article 1 <-> Article 2 (both read by B)
Article 2 <-> Article 3 (both read by B)
Article 2 <-> Article 4 (both read by C)
```

### CF Recommendation Pipeline

```typescript
// For User X who has read: [Article A]
// 1. Find similar users (Story 13.1): [User Y, User Z, User W]
// 2. Get their read history: Y=[A,B,C], Z=[A,D,E], W=[B,C,F]
// 3. Collect unread articles: [B, C, D, E, F] (remove A, X's read)
// 4. Score each:
//    - B: item_sim(A,B) * user_sim(X,Y) + item_sim(A,B) * user_sim(X,W) + ...
//    - C: item_sim(A,C) * user_sim(X,Y) + item_sim(A,C) * user_sim(X,W) + ...
// 5. Rank and return top-K
```

### Edge Case Handling

| Case | Handling |
|------|----------|
| **New article** | No readers yet → use content-based similarity (Story 12.5) |
| **Unpopular article** | Few co-reads → low confidence → blend with rules engine |
| **Highly read article** | Many readers → high co-read signal → reliable |
| **Sparse user** | Few reads → few similar users → low coverage → fallback |
| **Isolated article** | No co-reads → isolated in matrix → content fallback |
