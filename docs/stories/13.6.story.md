## Story

As a **recommendation system**, I want to **recommend articles outside the user's primary interests** so that **users discover new content, increase cross-topic engagement, and experience serendipitous discoveries that improve retention and platform stickiness**.

**Context:**
- Story 13.5 (Click-Prediction Neural Network) provides neural ranking with user click probability scores
- Story 13.1-13.3 (Collaborative Filtering) provides user similarity matrices and patterns
- Story 13.6 builds on CF patterns to identify articles the user *would enjoy* but *hasn't considered yet*
- Foundation for Stories 13.7-13.8 (advanced personalization features)

## IN Scope

- **Serendipity Scoring Algorithm**:
  - Input: User preference cluster (primary topics from CF), candidate articles, read history
  - Topic distance metric: How far article is from user's known interests (in topic embedding space)
  - Collaborative novelty: Articles recommended to similar users but not read by this user
  - Blending formula: novelty_score = (topic_distance * 0.4) + (collaborative_gap * 0.4) + (article_quality * 0.2)
  - Output: Serendipity score [0, 1] per article

- **Serendipity Ranking Integration**:
  - Extend rankArticles() with `serendipity_weight` parameter (default: 0.0)
  - Blend with click-prediction score: final_score = click_pred * (1 - serendipity_weight) + serendipity_score * serendipity_weight
  - Ensure diversity: avoid clustering similar serendipity articles (same topic)
  - Explain recommendations: show "You might enjoy this because..." messaging

- **Feature Flags & A/B Testing**:
  - Feature flag: `enable_serendipity_recommendations` (default: false)
  - A/B test harness: bucket users into control (standard ranking) vs. treatment (serendipity blending)
  - Track: discovery rate, cross-topic CTR, engagement metrics

- **Analytics & Monitoring**:
  - Serendipity discovery rate: % of recommended articles > 2 topics away
  - Cross-topic engagement: clicks on articles outside primary interests
  - Lift metrics: serendipity group vs. control group (CTR, time-on-page, bookmark rate)
  - Model drift: monitor if serendipity recommendations become stale

- **Cold-Start Handling**:
  - New users: use global topic popularity + random serendipity (broad discovery)
  - New articles: recommend immediately if topic-distant from similar users' interests

## Dev Notes

### Algorithm Design Decisions

1. **Blending Formula**: novelty_score = (topic_distance * 0.4) + (collaborative_gap * 0.4) + (article_quality * 0.2)
   - topic_distance: How far article is from user's known interests (in topic embedding space)
   - collaborative_gap: Articles similar users like but this user hasn't read
   - article_quality: Click-prediction probability (from Story 13.5)
   - Weighting: 40% novelty + 40% collaboration + 20% quality

2. **Topic Distance Metric**:
   - Use cosine similarity between article topic embedding and user primary topic embeddings
   - Distance = 1 - max_similarity (closer to 1 = more distant)
   - Threshold: articles with distance > 0.6 (2+ topics away)

3. **Diversity Constraint**:
   - Avoid returning multiple articles from same serendipity topic
   - Round-robin selection: pick top serendipity article, then next from different topic

4. **Cold-Start Handling**:
   - New users: use global topic popularity distribution
   - Recommend random serendipity articles across all topics

### Known Challenges

- **Topic embedding staleness**: Topic embeddings from Article Embeddings (Story 13.4) may not update frequently
  - Mitigation: weekly recomputation alongside Story 13.5 training
- **Serendipity fatigue**: Users may not want too many surprising recommendations
  - Mitigation: A/B test with different serendipity_weight values (0.1, 0.2, 0.3)
- **Filter bubble prevention**: Need balance between personalization and discovery
  - Mitigation: Monitor cross-topic engagement metrics
