## Story

**As a** site visitor  
**I want** to submit contact form and have my message stored  
**So that** CTRL + ALT News can respond to my inquiry

---

## Description

The ContactPage component (`client/src/pages/ContactPage.tsx`) currently simulates form submission with a mock `setTimeout(1200ms)` callback. This story implements real backend persistence by:

1. Creating a POST `/api/contact` endpoint in Express.js
2. Validating form data server-side (name, email, subject, message)
3. Storing contact submissions in the database (new `ContactSubmission` Prisma model)
4. Returning success/error response to frontend
5. Connecting frontend form to real API instead of mock

---

## Acceptance Criteria

### AC1: Backend Endpoint Created
**Given** a POST request to `/api/contact` with valid JSON body  
**When** body contains: `{ name, email, subject, message }`  
**Then** endpoint returns 201 status + `{ success: true, id: UUID, message: "Thank you..." }`

### AC2: Validation on Backend
**Given** invalid input (missing fields, invalid email)  
**When** POST `/api/contact` is called  
**Then** endpoint returns 400 status + `{ success: false, errors: { field: "error message" } }`

### AC3: Database Persistence
**Given** valid form submission  
**When** POST `/api/contact` succeeds  
**Then** data is stored in `ContactSubmission` table with: id, name, email, subject, message, createdAt

### AC4: Frontend Integration
**Given** user submits ContactPage form  
**When** form is valid and API returns 201  
**Then** success message displays and form resets + "Send another message" button appears

### AC5: Error Handling
**Given** API request fails (500, network error, etc.)  
**When** user submits form  
**Then** error toast displays: "Failed to send message. Please try again."

## Dev Notes

### Database Model (`ContactSubmission`)

```prisma
model ContactSubmission {
  id        String   @id @default(cuid())
  name      String   @db.VarChar(255)
  email     String   @db.VarChar(255)
  subject   String   @db.VarChar(500)
  message   String   @db.Text
  status    String   @default("NEW") // NEW, IN_PROGRESS, RESOLVED, SPAM
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime? // Soft delete

  @@index([email])
  @@index([createdAt])
}
```

### Endpoint Implementation

**Route:** `POST /api/contact`

**Request Body:**
```json
{
  "name": "John Doe",
  "email": "john@example.com",
  "subject": "Editorial Enquiry",
  "message": "I have a story idea..."
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "id": "cly9x8zq20000qz8z9x9x9x9x",
  "message": "Thank you for reaching out. Our team will get back to you within two business days."
}
```

**Response (400 Bad Request):**
```json
{
  "success": false,
  "errors": {
    "email": "Invalid email address",
    "message": "Message must be at least 20 characters"
  }
}
```

### Validation Rules

- `name`: required, 2-255 chars, no XSS
- `email`: required, valid RFC 5322 format
- `subject`: required, 5-500 chars
- `message`: required, 20-5000 chars
