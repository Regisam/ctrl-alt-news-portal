## Story

As a **development team**, I want to **establish end-to-end testing infrastructure** so that **we can validate critical user journeys and catch integration issues before production**.

**Context:**
- Story 15.1 & 15.2 completed async component testing and monitoring dashboards
- Unit tests verify component behavior, but E2E tests validate user workflows
- Critical paths need validation: article discovery → read → engagement → analytics
- Current test coverage: unit tests ✅, integration tests ⚠️, E2E tests ❌
- Team needs clear E2E test patterns to prevent regressions

**Goals:**
- Set up Playwright for E2E testing
- Create test fixtures for common user journeys
- Establish E2E test patterns and best practices
- Document E2E testing guide for team
- Achieve 80%+ coverage of critical user paths

## Dev Notes

### Context
- Test framework: Playwright (Browser Automation Library)
- Test location: `client/e2e/` (new directory)
- Config: `playwright.config.ts`
- CI integration: `.github/workflows/e2e.yml` (new)

### Critical User Journeys to Test

1. **Homepage → Search → Read**
   - Navigate to homepage
   - Search for article by keyword
   - Click result
   - Verify article detail loads
   - Verify analytics tracked

2. **Category Browse → Filter → Read**
   - Navigate to category page (e.g., /category/ai)
   - Apply filters (date range, trending)
   - Click article
   - Verify correct article loads

3. **Article Detail → Comments → Interaction**
   - Load article detail
   - Scroll to comments section
   - Submit comment (if logged in)
   - Verify comment appears
   - Verify real-time updates work

4. **Topic Recommendations → A/B Test → Click**
   - Load monitoring dashboard
   - Verify variant assignment shows
   - Click recommended topic
   - Verify adoption metric tracked
   - Verify cross-topic engagement recorded

5. **Real-Time Feed → New Article → Notification**
   - Open feed stream page
   - Trigger new article publish (via API or admin)
   - Verify new article appears in real-time
   - Verify notification sent (if enabled)
   - Verify user can interact with new article

### Estimated Effort Breakdown
- Playwright setup & configuration: 1.5h
- Test infrastructure & helpers: 2h
- Critical journey tests (5 tests): 2.5h
- Documentation & templates: 1h
- CI/CD integration: 1h

### Risks
- **Flaky tests**: Async operations and timing issues (mitigate with proper waits)
- **Test environment**: Database state must reset cleanly between tests
- **Performance**: Test suite must complete <5 minutes (timeout monitoring)
- **Maintenance**: E2E tests are fragile to UI changes (use stable selectors)

**Root Cause Analysis (by @qa):**
- Test failures traced to HTML selector mismatch
- Tests expected: `<article>` tags, `[data-testid="article-card"]`, `.article-card` class
- Components used: generic `<div>` without semantic markup or test IDs
- Impact: 87 tests failing across 5 test suites

**Solution Applied:**
- ✅ Updated ArticleCarousel.tsx: `<div>` → `<article data-testid="article-card" class="article-card">`
- ✅ Updated PersonalizedFeed.tsx: Added `<article data-testid="article-card">`
- ✅ Updated HeroSection.tsx: Added `data-testid="article-card"` to existing `<article>`
- ✅ Updated TrendingSection.tsx: Added `data-testid="article-card"` to existing `<article>`
- ✅ Updated GadgetsSection.tsx: Added `data-testid="article-card"` to existing `<article>`
