## 📌 Overview

**Serendipity Engine** is a production-ready ML feature that recommends articles outside users' primary interests to drive discovery, engagement, and retention. It blends collaborative filtering patterns with neural click predictions to deliver serendipitous recommendations with guardrails.

**Key Metric**: Target 15-20% cross-topic CTR lift vs. standard ranking (measured in Phase 3 A/B testing).

## 🏗️ Architecture

### Algorithm Design

```
Input: User engagement history + candidate articles
       ↓
[Topic Distance Metric] — How far article is from user's known interests
[Collaborative Novelty] — Do similar users like it but user hasn't read?
[Article Quality] — Click-prediction probability from neural model
       ↓
Blending Formula: (distance * 0.4) + (novelty * 0.4) + (quality * 0.2)
       ↓
Output: Serendipity score [0, 1] per article
```

### Integration Point

```
Story 13.5 (Click Predictions) + Story 13.6 (Serendipity)
       ↓
rankArticlesWithSerendipityIntegration()
       ↓
Blended Score: clickScore * (1 - weight) + serendipityScore * weight
       ↓
Output: Top-K articles with serendipity explanations
```

## ⚠️ Known Limitations & Future Work

### Current Limitations

1. **Topic Embeddings Staleness**: Article embeddings updated weekly (Story 13.4), may miss fast-moving topics
   - Mitigation: Monitor topic distance distribution; recompute if drift detected
   - Future: Real-time embedding updates (EPIC-14)

2. **Serendipity Fatigue**: Users may tire of surprising recommendations
   - Mitigation: A/B test different weight levels (0.1, 0.2, 0.3)
   - Future: Per-user serendipity budgets (EPIC-13 Phase 4)

3. **Cold-Start for New Topics**: Emerging topics have limited engagement history
   - Mitigation: Use global popularity + topic similarity
   - Future: Context-aware serendipity (time of day, device, mood)

### Out of Scope (EPIC-13 Phase 4+)

- Graph neural networks for user-article-topic relationships
- Multi-armed bandit optimization (dynamic weight tuning)
- Context-aware serendipity (temporal, situational)
- Conversational serendipity (user feedback loops)
- Personalized serendipity budgets

## 🎓 Technical Highlights

### Innovation Points

1. **Deterministic Bucketing**: User IDs → stable hash → consistent A/B assignment (no user switching between variants)
2. **Blending Formula**: Weighted average (40% novelty + 40% collaboration + 20% quality) balances discovery with relevance
3. **Diversity Constraints**: Round-robin topic selection prevents "serendipity fatigue" from similar suggestions
4. **Cold-Start Handling**: Graceful degradation for new users/articles (global popularity + topic similarity)

## 💬 Questions & Answers

**Q: Why 0.4 / 0.4 / 0.2 weights in the blending formula?**  
A: Empirical balance: topic novelty + collaborative credibility both matter equally; quality is a tiebreaker.

**Q: How does this avoid filter bubbles?**  
A: By explicitly recommending articles > 0.6 topic distance, we escape echo chambers. The serendipity weight controls the tradeoff between personalization and discovery.

**Q: What if a user doesn't want serendipitous recommendations?**  
A: Feature is disabled by default. Control group in A/B test gets standard ranking (no serendipity). Users can opt-out via preferences (future enhancement).

**Q: How do you handle model drift in click-prediction scores?**  
A: Story 13.5 retrains weekly. Serendipity scorer uses whatever click scores are provided; no separate retraining needed.
