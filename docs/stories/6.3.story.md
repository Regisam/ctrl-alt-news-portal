## Description

## Optimization Strategy

### Phase 1: Index Creation (Quick Wins)
```sql
CREATE INDEX idx_articles_user_id ON articles(userId);
CREATE INDEX idx_articles_category_id ON articles(categoryId);
CREATE INDEX idx_comments_article_id ON comments(articleId);
CREATE INDEX idx_comments_parent_id ON comments(parentId);
CREATE INDEX idx_comments_created_at ON comments(createdAt DESC);
CREATE INDEX idx_articles_user_created ON articles(userId, createdAt DESC);
```

### Phase 2: Query Optimization (Moderate Effort)
- Eager load relationships in Prisma
- Use `select()` to limit columns
- Implement pagination on large result sets
- Cache frequently accessed reference data

### Phase 3: Schema Review (Data Engineer)
- Analyze table bloat (VACUUM ANALYZE)
- Review column types (any VARCHAR that should be ENUM?)
- Consider denormalization for frequently computed values

## Query Optimization Examples

### Before (N+1 problem)
```typescript
const articles = await prisma.article.findMany()
// This causes N+1: one query for articles, then N queries for each author
const withAuthors = articles.map(a => ({
  ...a,
  author: await prisma.user.findUnique({ where: { id: a.userId } })
}))
```

### After (Eager load)
```typescript
const articles = await prisma.article.findMany({
  include: {
    author: { select: { id: true, name: true, avatar: true } },
    category: { select: { id: true, name: true } }
  },
  select: {
    id: true,
    title: true,
    excerpt: true,
    createdAt: true,
    // Don't select large fields (content, etc.)
  }
})
```
