## Story

As a **product team**, I want to **track system uptime and SLA compliance** so that **we can ensure service reliability, meet customer SLAs, and identify patterns of degradation**.

**Context:**
- Story 16.1 monitors system health (endpoints responding)
- No way to calculate uptime % or SLA compliance
- Need: Track downtime, calculate 99.9% uptime target
- Goal: Proactive alerting when SLA at risk

## IN Scope

- Health check sampling (every minute)
- Uptime % calculation (7/30/90 day windows)
- Configurable SLA targets
- Downtime event tracking + analysis
- SLA alert thresholds (e.g., if 99.8% uptime, alert before falling to 99.5%)
- Per-service uptime breakdown
- Dashboard integration (Story 16.3)
- Historical trend chart
- Incident correlation (link errors to downtime)
- Report export (CSV/PDF format)
- Maintenance window exclusion
- 365-day data retention

## Dev Notes

### Blockers
None identified.

### Gotchas
- Uptime calculation precision: floating point errors → use integer math
- Data growth: 1440 samples/day × 365 days = 525K records → use cleanup
- Anomalies: brief blips (10s) shouldn't count as downtime → use grace period
- Time zones: SLA windows in UTC or customer timezone?
- Maintenance windows: how to define/exclude them?
