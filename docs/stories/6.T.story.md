## Root Cause Analysis

### Issue Summary

During i18n migration (commits eedb56c-82f4d10), the `useLanguage` hook was introduced:

```typescript
// hook returns: string (dynamic, runtime value)
const language = useLanguage();  // "en" | "pt" at runtime, but typed as string

// but pages expect: literal type "en" | "pt"
const content = data[language];  // ❌ Type error: string is not assignable to "en" | "pt"
```

### Impact

- 106 TypeScript errors across 7 pages
- `npm run check` fails (CI/CD gate)
- Production build would fail
- Blocks ALL PR merges to main
- **Severity: CRITICAL**

### Solution Options

1. **Narrow return type of `useLanguage`** → Return `"en" | "pt"` instead of `string`
2. **Type assertion in consumers** → Add `as const` or type guard in each page
3. **Create language type helper** → Central type for all language handling

**Recommended**: Option 1 (cleanest, least error-prone)
