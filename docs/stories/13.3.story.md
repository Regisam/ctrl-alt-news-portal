## Story

As a **content discovery platform**, I want to **blend rules, content similarity, and collaborative filtering** into a **hybrid recommendation engine** so that **I can leverage all signals to deliver highly accurate, diverse recommendations that outperform any single approach**.

**Context:**
- Stories 13.1-13.2 established foundation: user similarity + item CF
- EPIC-12 established rules engine (Story 12.1) + content similarity (Story 12.5)
- Hybrid engine is Phase 1 culmination: integrate all signals with learned weighting
- Prerequisite for Story 13.4+ (neural models) and downstream recommendation features

## IN Scope

- **Ensemble Ranking**:
  - Score articles using 4 signals: rules engine, content similarity, collaborative filtering, popularity
  - Normalize scores to [0, 1] range
  - Blend with configurable weights (tuple: [w_rules, w_content, w_cf, w_popularity])
  - Final score = w1*rules + w2*content + w3*cf + w4*popularity

- **Feature Weighting**:
  - Initial weights based on EPIC-12 success: rules=30%, content=40%, CF=30%, popularity=0%
  - Weights configurable via YAML/environment for A/B testing
  - Weight tuning based on A/B test results

- **Recommendation Diversity**:
  - Topic diversity: avoid recommending 3 AI articles in top-5
  - Author diversity: avoid over-recommending same author
  - Recency diversity: mix recent + older articles
  - Penalty term: reduce score for articles similar to already-recommended

- **Explainability**:
  - Return reason for each recommendation (e.g., "Trending (rules) + Similarity (content) + Users like you (CF)")
  - Show contributing signals in order of contribution
  - User-facing explanation: "This article is recommended because..."

- **A/B Testing**:
  - Control: rules-only recommendations
  - Treatment: hybrid recommendations
  - Metrics: CTR, engagement time, feedback (thumbs up/down)
  - Statistical significance testing (p<0.05)

- **Performance**:
  - Latency budget: <50ms per recommendation
  - Breakdown: rules <5ms, content <15ms, CF <20ms, blend <10ms
  - Caching for frequently scored articles

- **Tests**:
  - Unit: scoring formula, weight blending, diversity penalty
  - Integration: end-to-end recommendations with all signals
  - Edge cases: new article, sparse user, heavy diversification

## Technical Details

### Component Structure

```typescript
// hybridRecommendationEngine.ts
export interface RecommendationSignal {
  articleId: string;
  score: number; // [0, 1] normalized
  source: 'rules' | 'content' | 'cf' | 'popularity';
}

export interface HybridRecommendation {
  articleId: string;
  finalScore: number; // [0, 1]
  signals: RecommendationSignal[]; // breakdown by source
  reason: string; // explainability: "Trending (rules: 0.8) + Similar (content: 0.7) + Users like you (CF: 0.6)"
}

export interface EnsembleWeights {
  rules: number; // typically 0.3
  content: number; // typically 0.4
  cf: number; // typically 0.3
  popularity: number; // typically 0.0
}

export interface HybridEngineConfig {
  weights: EnsembleWeights;
  diversityPenalty: number; // [0, 1], how much to penalize similar articles
  topK: number; // return top-K recommendations
  minTopicDiversity: number; // e.g., 0.6 = at least 60% different topics
}

export async function generateHybridRecommendations(
  userId: string,
  rules: RecommendationEngine, // Story 12.1
  contentSimilarity: ContentSimilarityEngine, // Story 12.5
  collaborativeFiltering: CFEngine, // Story 13.2
  config: HybridEngineConfig
): Promise<HybridRecommendation[]> {
  // 1. Get candidate articles from each signal
  const rulesRecs = await rules.getRecommendations(userId, config.topK * 2);
  const contentRecs = await contentSimilarity.getRecommendations(userId, config.topK * 2);
  const cfRecs = await collaborativeFiltering.getRecommendations(userId, config.topK * 2);

  // 2. Score each article by all signals
  const articleScores = new Map<string, RecommendationSignal[]>();
  
  // 3. Normalize and blend
  const hybridScores = normalizeAndBlend(articleScores, config.weights);

  // 4. Apply diversity constraints
  const diverse = enforceTopicDiversity(hybridScores, config.minTopicDiversity);

  // 5. Rank and return top-K with explainability
  return generateExplanations(diverse.slice(0, config.topK));
}

export function normalizeAndBlend(
  scoresBySource: Map<string, RecommendationSignal[]>,
  weights: EnsembleWeights
): Map<string, number> {
  const blended = new Map<string, number>();
  
  for (const [articleId, signals] of scoresBySource) {
    const rulesScore = signals.find(s => s.source === 'rules')?.score ?? 0;
    const contentScore = signals.find(s => s.source === 'content')?.score ?? 0;
    const cfScore = signals.find(s => s.source === 'cf')?.score ?? 0;
    const popScore = signals.find(s => s.source === 'popularity')?.score ?? 0;

    const final = 
      weights.rules * rulesScore +
      weights.content * contentScore +
      weights.cf * cfScore +
      weights.popularity * popScore;

    blended.set(articleId, final);
  }

  return blended;
}

export function enforceTopicDiversity(
  rankings: Array<{ articleId: string; score: number }>,
  minDiversity: number
): Array<{ articleId: string; score: number }> {
  const result: Array<{ articleId: string; score: number }> = [];
  const topicsSelected = new Map<string, number>(); // topic -> count
  let totalTopics = new Set<string>();

  for (const { articleId, score } of rankings) {
    const topic = getArticleTopic(articleId);
    const topicCount = topicsSelected.get(topic) ?? 0;

    // Penalty if topic over-represented
    const diversityPenalty = (topicCount + 1) / result.length;
    const penalizedScore = score * (1 - diversityPenalty);

    if (penalizedScore > 0) {
      result.push({ articleId, score: penalizedScore });
      topicsSelected.set(topic, topicCount + 1);
      totalTopics.add(topic);
    }
  }

  return result;
}

export function generateExplanations(
  recommendations: Array<{ articleId: string; score: number; signals: RecommendationSignal[] }>
): HybridRecommendation[] {
  return recommendations.map(({ articleId, score, signals }) => {
    // Sort signals by contribution (descending)
    const sorted = signals.sort((a, b) => b.score - a.score);
    
    // Build readable explanation
    const reason = sorted
      .filter(s => s.score > 0.1) // Only include signals above threshold
      .map(s => `${capitalizeSource(s.source)}: ${(s.score * 100).toFixed(0)}%`)
      .join(' + ');

    return {
      articleId,
      finalScore: score,
      signals,
      reason: `Recommended because: ${reason}`
    };
  });
}
```

## Dev Notes

### Tech Stack Decisions
- **Weighted averaging**: Simple, interpretable, easy to tune
- **Configuration-based weights**: YAML for easy experiment management
- **Diversity penalty**: Multiplicative (multiplicative > additive for this use case)
- **Explainability**: Signal breakdown shown to user

### Performance Targets
- Ensemble scoring: <10ms
- Diversity enforcement: <5ms
- Explainability: <5ms
- Total: <50ms per recommendation

### Testing Strategy
- **Unit**: Scoring formula, diversity penalty, explanation generation
- **Integration**: End-to-end with all signals
- **A/B test**: Control (rules) vs. treatment (hybrid), measure CTR/engagement

### A/B Test Design
- Duration: 2 weeks (sufficient sample size for 30%+ CTR improvement detection)
- Metrics: click-through rate, engagement time, user feedback (thumbs)
- Significance: p<0.05
- Minimum detectable effect: +5% CTR
